OPERATING RULES

- Work autonomously in the assigned disposable environment. Install ordinary
  build/runtime prerequisites, provision test accounts/data, and use available
  infrastructure. Solve setup problems rather than sending the user a shopping
  list. Use secure credential input if access is genuinely missing; never put
  passwords/tokens in the report. Ask only for access or consequential choices
  you cannot resolve within the assigned environment.
- Preserve pre-existing source changes and user data. Use disposable roots and
  accounts. Do not change Defender, weaken system-wide permissions, disable app
  protections, or run the whole app elevated to manufacture a pass. Limited
  elevation for prerequisite installation and the app's intended UAC flows is
  fine. Normal use and native permission assertions must run unelevated.
- Use repository AGENTS.md and relevant skills when editing. Keep fixes focused
  in existing owners. Do not replace the architecture, remove features, loosen
  acceptance assertions, skip tests, or add speculative security controls.
- A guard is correct only if it rejects the unsafe case AND permits ordinary
  use. Test both sides and the recovery after the condition clears. A harmless
  executable reader must not block setup; stock RetroBat files must not make
  integration unusable; unrelated failures must not stop healthy games/saves.
- Computer-use must drive the actual user journeys. Shell/API calls may prepare
  test data and independently verify results; they cannot substitute for the
  UI action under test. Do not edit settings/journals/ownership markers to get
  past broken UI. Keep any diagnostic workaround separate from a product pass.
- Do not stop the entire run at a failure. Preserve the first failure, diagnose,
  repair, retest, and continue independent cases. Use bounded waits (normally
  60 seconds after debounce for a small local operation); downloads/builds get
  sensible progress-based limits. Never retry until green and hide the failures.

4. COMPUTER-USE ACCEPTANCE CASES

AUTH — Fresh profile: browser pairing, cancel, retry, approve; password fallback
and wrong password; remembered restart; sign-out and token revocation in RomM;
reauthenticate without losing the chosen folder. Switch between disposable
accounts/server identities and confirm catalogue, consent and pending operations
do not leak. A repeated pairing must provide a usable new approval flow, not a
consumed URL. Password/token values must not appear in screenshots/shared logs.

SETUP — Follow Connect -> select folders/RetroBat -> Connect RetroBat -> start
games folder. Also complete Generic folders without RetroBat. Fresh RetroBat
with bundled games/configuration must work without deleting its stock content
or first mounting and then stopping just to finish onboarding. Test a path
with spaces/non-ASCII characters. Browse and cancel native folder pickers.
Exercise needed UAC approval and cancellation, then retry normally. Routine
use must not require running RomMFS as administrator or hand-editing files.

MOUNT — Enumerate before reading and prove no ROM downloads with controlled
native counters. Cold read matches the known source hash; warm read uses cached
bytes. Play through the mounted path. Stop/start and Quit/reopen preserve owned
placeholders, file identities and downloaded bytes; unchanged restart creates
and removes zero placeholders. Test an actual catalogue addition/content change:
refresh preserves the running snapshot; Apply library changes exposes the new
tree. Identical/artwork-only refresh does not demand remount. Exercise safe
eviction/re-download and busy-file deferral through the native regression.
Try a populated unowned root and a root owned by another server; rejection
preserves sentinels and offers a usable route to select a suitable folder.

RETROBAT — Discover/select the actual install, including Browse outside the
default location. Integrate alongside stock/user games. Verify per-system RomM
links and merged gamelists, idempotent setup, and preservation of unrelated
entries. A foreign link or conflicting item affects only its system, with an
explanation. Remove one tester-owned link: focus/refresh clears false healthy
status and Stop and repair restores operation through the UI. Test the real
frontend running and a harmless read handle on its executable separately:
the reader must not block setup; the frontend delays only affected publication.
Close the frontend; automatic retry and explicit Retry recover without restart.
An unrelated installation's frontend must not lock this one. Do not require
the RetroBat launcher itself to stay alive after handing off to EmulationStation.

PLAY — Launch the genuine frontend and a real playable title through RomMFS.
Interact, create identifiable saved progress, exit cleanly, launch again and
load that progress. Create and load a save state too. Verify the actual save
paths are outside the ROM mount. Collect short visual evidence of gameplay
and restored progress, plus ROM/save hashes. Fix supported runtime/display
configuration in the disposable host if needed; record it. A process name or
startup screenshot alone is not a gameplay pass.

METADATA — Observe artwork and gamelist publication in the real frontend.
Refresh unchanged data: no unnecessary image replacement/download. Delete one
owned image: only that image needs restoration. Favourite/play a game, remount
and refresh; favourites/history survive. Create one destination write failure:
other systems and games remain usable, status says Updated with issues, and
Retry recovers after access is restored. Overview/Settings/Activity agree.

HISTORY — Enable the separate favourites/play-history consent. Make a favourite
change in each direction and a new real play session; verify RomM and RetroBat
converge without repeated refreshes multiplying counts/time or uploading old
plays again. Disable and change account: consent does not carry over. Missing
permission affects this feature with a useful remedy, not ROM availability.

DUPLICATES — Put a lawful matching local game alongside its RomM copy. Hide
RomM games you already have hides only the RomM entry. Toggle it off or remove
the disposable local duplicate: that entry returns; user-hidden games, local
bytes, favourites and history remain intact. Include a same-name nonmatch and
the documented large-file fallback in appropriate existing fixture coverage.

SAVES — Verify default Off is quiet, not an alarm; filename preview does not
upload or read save bodies. Stock/unmatched files stay understandable and do
not prevent healthy mapped saves syncing. Exercise explicit file/folder mapping
and confirm only intended paths are associated. Verify game/account/root and
save API access before starting app-only traffic capture; do not count tester
API requests as app requests. Use independent A/B scopes for these subcases:

  S1. Enable explicitly. Upload a real emulator-created save from A. Download
      the exact remote revision independently and compare bytes. Restore to a
      genuinely new B path, launch the game there and load the same progress.
      Include a real save-state round trip; supported saves must not be SRAM-only.
  S2. Round-trip companions, nested/extensionless files, empty files and a file
      larger than 1 MiB. Compare exact relative paths and hashes. Newly created
      files are noticed without waiting for the fallback scan; incoming writes
      do not echo into endless duplicate revisions.
  S3. With a verified baseline, change only remote. The unchanged local baseline
      is safely replaced and a recoverable backup retained. Hold the real target
      busy, then release it: defer and recover without loss or permanent refusal.
  S4. Establish baseline X, different local Y and different remote Z. Confirm
      conflict preserves both copies. Export writes exact Z to a fresh path,
      refuses clobbering an existing/mapped destination and does not clear review.
      Disable sync, restart and export again offline: review persists, and this
      staged export needs no save API request. Test the native filename field
      by replacing its text, catching the historical concatenation bug.
  S5. Choose Keep this PC's save through the UI. Y uploads as a new revision;
      remote copies remain, review resolves and survives restart. Repeat in a
      separate conflict with Use this RomM copy: Z becomes local and Y remains
      recoverable. A later local edit syncs normally. A changed local file after
      review requires a fresh choice; unchanged acknowledged remote history
      must not immediately recreate the conflict. New competing history must.
  S6. Stop the test server, change a tracked save and wait past debounce. Quit,
      restart, restore server and reconnect: queued bytes survive and upload.
      No successful/up-to-date status before verification. Do not clear the
      journal/cache or re-onboard to recover an ordinary outage.
  S7. Delete a previously tracked disposable save while sync is disabled, then
      enable. It stays absent and the remote copy stays intact. An explicit
      reviewed Use RomM choice may restore it; silent resurrection may not.
  S8. Switch account/server/root, disable, sign out and Quit during work. Old
      consent/results cannot write into the new scope. One conflicted save
      does not block a healthy save. Use deterministic held-request tests to
      prove cancellation boundaries that cannot be timed reliably by clicking.

CARDS — Do not omit the current PS1/PS2 feature because the old checklist says
shared cards are unsupported. Exercise DuckStation .mcd, PCSX2 .ps2 and folder
cards with independent per-folder opt-in, the actual real-server routes and

then sync resumes. Remote-only changes update an unchanged baseline; competing
changes preserve local plus version-specific conflict siblings. A broken card
does not stop another, and ordinary save mapping excludes these folders. Verify
restored real cards are recognized by the emulator's card UI where available.
Use fixtures for malformed/unsafe zip cases. Do not require commercial BIOS or
games to test archive transport, consent and file/card recognition. External
broker/container-client interoperability is supplemental unless it is actually
part of this checkout's exposed user workflow; identify that boundary explicitly.

INSTALLER / SUPPORT — Through the app, download the official installer, cancel
and retry, launch its real wizard, cancel there, then complete an installation.
Verify integrity checking and usable success/error/cancel states; don't count
an exit code as installation. Never kill a writing installer. Install available
lawful support files and harmless test payloads through the supported BIOS,
keys/unpacked firmware and RetroArch cheat routes; check effective destinations
and bytes, repeat reuse, cancellation, unsupported input diagnostics and
preservation of existing/modified files. Synthetic payloads prove materialization,
not firmware boot. Missing proprietary material does not block these tests.
An optional support-file problem must not mark working games unavailable.

DESKTOP / RECOVERY — Visit every page and visible action with mouse and keyboard.
Tab/Shift+Tab has visible sensible focus; Enter/Space activate once; Space types
normally in text fields; Escape cancels dialogs without losing state. Resize
and use an available larger display scale: controls/errors remain reachable.
Try a few thousand synthetic catalogue/review entries using existing fixtures
and generators; verify search, filtering, pagination, counts and mapping of a
late-page entry. Measure first-use and repeat mount/refresh times, and capture
any long freeze or misleading progress. Do not invent hardware benchmark gates.
Activity must show real work, useful error/retry and readable bounded logs,
without per-tick floods. Recover outages and permission failures from the UI.

LIFECYCLE — Hide the window while mounting/syncing; work continues. Reopen from
tray, including after --startup: all pages/sidebar render. Launch a second
instance: it activates the first without another mount/worker. Enable login
startup with remembered sign-in; perform an actual sign-out/sign-in cycle in
the disposable Windows session if the host allows it. Authenticate -> mount ->
resume only previously consented sync, in that order. Test rejected auth and a
failed mount: visible recovery, no unauthorized sync. Disable startup/logout:
registration is removed. Quit during catalogue, hydration or save work: owned
workers drain, no stale completion reactivates a session, roots/data remain safe.
